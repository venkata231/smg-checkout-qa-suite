🛡️ QA Best Practices: Test Triage & Defect Strategy
Test Suite Hygiene & Known Defect Policy

Rules for managing test failures to maintain test suite credibility and distinguish real application defects from test suite issues.

✅ Only Leave a Failing Test When:

  • The defect is confirmed by QA/Dev.
  • The expected result matches agreed requirements.
  • The test itself is stable and correctly implemented.

🛠️ Fix or Remove a Test When It Fails Due To:

  • An unstable or fragile locator.
  • Incorrect test data setup.
  • Timing or race conditions.
  • Dependency on another test case state.
  • An incorrect or outdated assertion.
🏷️ Known Defect Tagging Standard (Example):
@known-defect @BUG-013 Scenario: Declined card should not create an order Given the shopper has products ready for checkout And valid delivery details have been provided And the shopper enters test declined card "4000000000000002" And the shopper accepts the checkout terms When the shopper attempts to place the order Then the payment should be declined And a confirmed order should not be created
