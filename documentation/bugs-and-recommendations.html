Defect Reports & UX Recommendations

Detailed functional bugs (BUG-001 to BUG-014), observations, and UX recommendations logged during testing.

Functional Defects

BUG-001 – Search input loses focus when results update
Severity: Low Priority: Medium
Found During: Exploratory Testing / CAT-11
Steps to Reproduce
  1. Navigate to Shop & basket.
  2. Click the Search field.
  3. Begin entering a search term.
  4. Wait for the product results to update.
  5. Attempt to continue typing.
Expected Result
Focus should remain in the Search field while results update, allowing the user to continue typing without additional interaction.
Actual Result
The Search field loses focus when results update. User must click back into the field before continuing to type.
Impact
Interrupts the search journey and creates unnecessary interaction friction for the user.
BUG-002 – Purchased items remain in basket after successful checkout
Severity: Medium Priority: High
Found During: Exploratory Testing / BAS-12 / PAY-07
Steps to Reproduce
  1. Add a product to the basket.
  2. Complete checkout successfully.
  3. Confirm that the order has been created.
  4. Navigate back to Shop & basket.
  5. Observe the basket contents.
Expected Result
Products included in a successfully completed order should be cleared from the active basket.
Actual Result
Purchased products remain in the active basket and can be taken through checkout again.
Impact
Customers may accidentally place duplicate orders, and the basket state does not accurately reflect completed transactions.
BUG-003 – Basket quantity is capped at 5 despite higher available stock
Severity: Medium Priority: High
Found During: Exploratory Testing / BAS-06 / BAS-08
Steps to Reproduce
  1. Select a product showing more than 5 units in stock.
  2. Add the product to the basket.
  3. Increase the quantity to 5.
  4. Attempt to increase the quantity to 6.
Expected Result
The customer should be able to increase quantity up to available stock unless a max-per-order rule is defined.
Actual Result
Quantity cannot exceed 5. Application states maximum quantity is 5 despite showing higher available stock.
BUG-005 – Checkout navigation continues to show "Pay" after order completion
Severity: Low Priority: Medium
Found During: Exploratory Testing / PAY-05 / NAV-05
Actual Result
Checkout/payment navigation item continues to display Pay after successful order completion.
BUG-006 – Product search does not return results when searching by SKU
Severity: Medium Priority: Medium
Found During: Focused Testing – CAT-03
Actual Result
Searching exact SKU (e.g. SKU-AUD-PODS) displays "No products found".
BUG-008 – Same promotional code can be applied multiple times
Severity: High Priority: High
Found During: Focused Testing – PRO-08
Actual Result
Applying WELCOME5 three times creates three applied promotions and gives a total discount of £15.
BUG-009 – Checkout accepts invalid card number formats
Severity: High Priority: High
Found During: Focused Testing – CHK-08
Actual Result
Checkout accepts arbitrary invalid card strings and allows order to be placed successfully.
BUG-010 – Multiple orders created when Place Order is clicked rapidly
Severity: High Priority: High
Found During: Focused Testing – PAY-04
Actual Result
Rapid clicks create multiple confirmed orders (up to 9 orders created for single transaction during testing).
BUG-012 – CSV export contains incorrect final order totals
Severity: High Priority: High
Found During: Focused Testing – ORD-09 / ORD-12
Actual Result
CSV Total column contains original subtotal without subtracting promotional discounts or adding delivery fees.
BUG-013 – Order is successfully created using declined test card
Severity: High Priority: High
Found During: Focused Testing – PAY-02
Actual Result
Entering test declined card 4000000000000002 is accepted and order is confirmed.
BUG-014 – Multiple different promotional offers can be combined
Severity: High Priority: High
Found During: Focused Testing – PRO-06
Actual Result
Both WELCOME5 (£5) and SAVE10 (10%) can be combined on same order violating promo policy.

UX & Product Recommendations

REC-001 – Clearly indicate mandatory checkout fields
Add visual asterisks or "Required" labels to Address Line 1, Postcode, Card Number, and Terms checkbox to prevent user submission errors.
REC-002 – Improve text formatting and pluralisation
Fix product title and SKU spacing. Use dynamic grammatically correct pluralisation (e.g. "1 item line, 1 item" vs "2 item lines, 5 items").
REC-003 – Clarify Express delivery pricing
Display "Express – £7.99 (Free over £50)" so users understand why charge drops to £0 for orders over £50.
REC-004 – Provide option to remove applied promo code
Provide a clear "Remove" button next to applied promo codes so shoppers can change promotions without resetting checkout state.
REC-005 – Provide access to individual order details
Allow users to click an Order ID row in Order History to view full line-item details, applied promo discounts, and delivery breakdown.
